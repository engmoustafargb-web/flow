# 03.01 __ 14. Classes - الشرح المبسط

---

## 1. الحكاية والتشبيه (Analogy)
تخيل إنك صاحب مصنع كحك وبسكوت، وعندك قطّاعة كحك حديد (بنسميها الـ `cookie cutter`). 

- الـ قطّاعة الحديد دي مش كحكة في حد ذاتها، هي مجرد فورمة أو قالب بيحدد الشكل الأساسي. دي بنسميها الـ `Class`.
- لما تضغط بالقطّاعة على العجين، بتعمل كحكة حقيقية ملموسة تقدر تاكلها. الكحكة دي بنسميها الـ `Object` أو الـ `Instance`.

الجميل هنا إنك تقدر تستخدم نفس القطّاعة عشان تعمل 100 كحكة؛ وكل كحكة ممكن ترش عليها سكر مختلف، أو تحط عليها لون مختلف (واحدة خضراء، واحدة زرقاء، واحدة صفراء). القطّاعة حددت الشكل، لكن كل كحكة ليها خصائصها المستقلة.

---

## 2. تعريف المفهوم (Core Concept)
- **يعني إيه Class؟**: هو قالب أو مخطط بتصممه مرة واحدة عشان تنشئ منه كائنات (`objects`) متعددة ليها نفس الهيكل والوظائف.
- **ليه بنستخدمه؟**: عشان نجمع البيانات (الخصائص أو الـ `properties`) والأفعال (الـ `methods` أو الـ `functions`) في مكان واحد منظم وسهل التكرار.
- **المشكلة اللي بيحلها**: بيمنع تكرار كود إنشاء الكائنات يدوياً. لو معندناش الـ `Class` وحبينا نعمل 100 مستخدم أو 100 عقدة في القائمة (`nodes`)، كنا هنضطر نكتب الهيكل بتاعهم يدوياً لكل واحد، وده تضييع وقت وعرضة للأخطاء.

---

## 3. الفرق بينه وبين البدائل (Differences)
تعال نشوف الفرق بين القالب والنسخة الفعلية، وبين وظائف التحكم الأساسية:

| وجه المقارنة | الـ `Class` (القالب) | الـ `Instance` (النسخة) |
|---|---|---|
| **الفكرة الأساسية** | هي قطّاعة الكوكيز (الرسم الهندسي). | هي الكحكة الحقيقية في الـ `memory`. |
| **طريقة الإنشاء** | بنكتبها بكلمة `class`. | بننشئها باستخدام كلمة `new`. |

وأيضاً جوه الـ `Class` بنقسم الوظائف لنوعين رئيسيين:
- **الـ Getter (`get color`)**: وظيفة بتجيب وتستعرض قيمة خاصية معينة.
- **الـ Setter (`set color`)**: وظيفة بتعدل وتغير قيمة خاصية معينة.

---

## 4. النموذج الذهني (Mental Model)
تخيل الـ `Class` كأنها استمارة تقديم فارغة مصممة في مصلحة حكومية. الاستمارة دي بتحدد البيانات المطلوبة (الاسم، السن، العنوان). 
الـ `new Class()` هي عملية طباعة نسخة ورقية حقيقية من الاستمارة دي وكتابة بيانات مواطن محدد عليها. المواطن الأول بياناته مختلفة عن المواطن التاني، بس الاتنين ماليين نفس شكل الاستمارة بالظبط.

---

## 5. طريقة الكتابة والشرح خطوة بخطوة (Syntax Breakdown)
بص معايا، دي طريقة كتابة الـ `Class` الأساسية في الـ `JavaScript`:

```javascript
class Cookie {
    constructor(color) {
        this.color = color;
    }

    getColor() {
        return this.color;
    }

    setColor(newColor) {
        this.color = newColor;
    }
}
```

تعال نشوف الكود ده سطر سطر بيعمل إيه:
1. **`class Cookie`**: بنعلن عن إنشاء `class` جديدة واسمها بيبدأ بحرف كابيتال دايماً.
2. **`constructor(color)`**: ده الـ `constructor`؛ وهي الـ `function` اللي بتشتغل تلقائياً أول ما ننشئ نسخة جديدة عشان تحدد الخصائص الابتدائية.
3. **`this.color = color`**: كلمة `this` بتشاور على النسخة المحددة اللي بنعملها حالياً في الذاكرة. يعني بنقول: "خلي لون الكوكيزاية الحالية بيساوي اللون اللي مبعوت لي".
4. **`getColor()`**: دي `getter method` عشان ترجع اللون الحالي.
5. **`setColor(newColor)`**: دي `setter method` بتستقبل لون جديد وتغير لون النسخة الحالية ليه.

تعال ننشئ النسخ دي:
```javascript
let cookieOne = new Cookie('green'); // نسخة خضراء
let cookieTwo = new Cookie('blue');  // نسخة زرقاء
```

---

## 6. الحالات المختلفة (Cases Comparison)
استخدام كلمة `this` بيختلف حسب الكيان اللي بيناديها:

- **لو نادينا `cookieOne.getColor()`**: كلمة `this` جوه الـ `Class` بتتحول وتطير تشاور على الكائن `cookieOne` بالظبط، فبترجع اللون بتاعه وهو `green`.
- **لو نادينا `cookieTwo.getColor()`**: كلمة `this` بتتحول وتشاور على الكائن `cookieTwo` بالظبط، فبترجع اللون بتاعه وهو `blue`.

---

## 7. أمثلة عملية من الواقع (Real-World Examples)
كل هياكل البيانات اللي هنبنيها في الكورس ده بتعتمد على الـ `Classes`. تعال نشوف إزاي بنبني قالب للعقدة (`Node`) اللي بنستخدمها في الـ `Linked List`:

```javascript
class Node {
    constructor(value) {
        this.value = value; // القيمة اللي متخزنة جوه العقدة
        this.next = null;   // مؤشر بيشاور على العقدة اللي بعديها
    }
}
```

---

## 8. تتبع التنفيذ خطوة بخطوة (Step-by-Step Execution)
لو شغلنا السطر ده: `let myNode = new Node(23);`

1. كلمة `new` بتحجز مكان جديد وفاضي في الذاكرة الـ `heap`.
2. بيتم استدعاء الـ `constructor` وتمرير القيمة `23` ليه.
3. الـ `constructor` بيشغل الكود ويخلي `this.value = 23` و `this.next = null`.
4. الـ `constructor` بيرجع الكائن الجديد اللي اتعمل، والـ `variable` اللي اسمه `myNode` بيمسكه ويبدأ يشاور عليه.
النتيجة في الذاكرة كائن بالشكل ده: `{ value: 23, next: null }`.

---

## 9. دورة الحياة والتنظيف (Lifecycle & Cleanup)
لما بننشئ كائن جديد باستخدام `new`، بيتحجز له مكان في الـ `memory`. الكائن ده بيفضل عايش طول ما فيه `variables` بتشاور عليه. أول ما المتغيرات دي تتشال أو الكود يخلص، الكائن ده بيموت والـ `JavaScript engine` بيمسحه تلقائياً عشان يوفر مساحة.

---

## 10. جدول الأخطاء الشائعة (Common Mistakes Matrix)
بص هنا، دي أشهر غلطة الناس بتقع فيها وهما بينادوا الـ `Class`:

### الغلطة الأولى: نسيان كلمة `new` عند إنشاء نسخة جديدة من الـ `Class`
- **إيه اللي بيحصل؟ (Symptom)**: الكود بيطلع خطأ في الـ `console` بيقول: `TypeError: Class constructor Cookie cannot be invoked without 'new'`.
- **ليه ده بيحصل؟ (Why)**: لأن الـ `JavaScript` في معيار الـ `ES6` بتمنع تماماً استدعاء الـ `Class` كأنها `function` عادية؛ لازم تستخدم كلمة `new` عشان تفهم المتصفح إنه يبني كائن جديد في الذاكرة.
- **نصلحها إزاي؟ (Fix)**:
  حط كلمة `new` دايماً قبل اسم الـ `Class`:
  ```javascript
  // غلط:
  let c1 = Cookie('green');

  // صح:
  let c1 = new Cookie('green');
  ```
- **القاعدة اللي تحميك**: أي `Class` في الـ `JavaScript` عشان تشتغل وتولد كائن لازم يسبقها كلمة `new`.

---

## 11. خلاصة سريعة (Recap)
عشان نربط الخيوط ببعضها:
- الـ `Class` قالب (قطّاعة) والـ `Instance` هو الكائن الفعلي (الكحكة).
- الـ `constructor` هو المسؤول عن تعيين القيم المبدئية للكائن.
- كلمة `this` بتشاور دايماً على الكائن المحدد اللي بيتم التعامل معاه حالياً.
- **افتكر دايماً**: الـ `Classes` هي حجر الأساس اللي هنبني بيه كل هياكل البيانات الجاية، زي الـ `Linked Lists` والـ `Trees` والـ `Graphs`!
