# 04.14 __ 30. LL- Reverse - Explained

---

## 1. Analogy / Story
Imagine a line of people holding shoulders. Each person has their hands on the shoulders of the person *in front* of them, looking towards the leader (`head`). You want to reverse this line so everyone faces the opposite direction and holds the shoulders of the person *behind* them.

- **The Setup**: First, you swap the roles of the ends. The person who was the leader (`head`) becomes the new follower (`tail`), and the person who was the follower becomes the new leader.
- **The Loop**: To make them turn around and hold shoulders in the other direction without anyone getting lost, you need three roles:
  1. `temp`: The current person you are instructing.
  2. `prev`: The person behind `temp` in the new order (initially nobody / `null`).
  3. `next`: The person in front of `temp` in the old order, who acts as an anchor so `temp` doesn't lose the line when they turn around.
- **The Action**:
  1. You locate the person in front: `next = temp.next`.
  2. You tell `temp` to let go of the person in front and place their hands on the shoulders of `prev`: `temp.next = prev`.
  3. Now `temp` becomes the new `prev` for the next person: `prev = temp`.
  4. Finally, you move to the next person you anchored earlier: `temp = next`.
  Repeat this process until everyone has turned around.

---

## 2. Core Concept
- **What is Reverse in a Linked List?**: It is the process of reversing the order of all nodes in a linked list, making the old tail the new head, the old head the new tail, and reversing the direction of all the next pointers.
- **Why do we use it?**: It is a classic coding interview problem that tests your understanding of pointer manipulation and memory tracking.
- **The Problem it Solves**: It reverses a list in-place with `O(n)` linear time complexity and `O(1)` constant space complexity, without allocating any extra nodes or copying data.

---

## 3. Differences / Comparisons
Let's compare reversing a `Linked List` versus reversing an `Array`:

| Aspect | `Array` | `Linked List` |
|---|---|---|
| **Space Complexity** | `O(n)` if a new array is allocated, or `O(1)` if done in-place by swapping elements. | Always `O(1)` space because we only flip existing pointer directions. |
| **Ease of Implementation** | Very simple, often built into the language (e.g. `arr.reverse()`). | Complex, requiring careful tracking of 3 sliding pointers to avoid losing references. |

---

## 4. Mental Model
Think of `reverse` as flipping links in a chain one by one:
1. Swap `head` and `tail` pointers of the list.
2. Initialize three tracking pointers: `temp` at the old head, `prev` as `null` (since the old head won't point to anything when reversed), and `next` to hold the remainder of the list.
3. Loop through the list:
   - Save the next node: `next = temp.next`.
   - Reverse the current pointer: `temp.next = prev`.
   - Move `prev` forward to the current node: `prev = temp`.
   - Move `temp` forward to the saved next node: `temp = next`.
4. Stop when `temp` becomes `null`.

---

## 5. Syntax & Step-by-Step Breakdown
Here is the JavaScript implementation of the `reverse` method:

```javascript
reverse() {
    let temp = this.head;
    this.head = this.tail;
    this.tail = temp;
    let next = temp.next;
    let prev = null;
    for (let i = 0; i < this.length; i++) {
        next = temp.next;
        temp.next = prev;
        prev = temp;
        temp = next;
    }
    return this;
}
```

Let's break down the logic line-by-line:
1. **`let temp = this.head;`**: Save the original `head` reference in a temporary variable `temp`.
2. **`this.head = this.tail;`**: Reassign `head` to point to the `tail` node.
3. **`this.tail = temp;`**: Reassign `tail` to point to the old head stored in `temp`.
4. **`let next = temp.next;`**: Set up a `next` variable to point to the node after `temp`.
5. **`let prev = null;`**: Initialize `prev` to `null`. The first node we reverse (the old head) will point to `null` because it becomes the new tail.
6. **`for (let i = 0; i < this.length; i++)`**: Loop exactly as many times as there are nodes in the list.
7. **`next = temp.next;`**: Inside the loop, first store the next node so we don't lose the rest of the list when we rewrite the pointer.
8. **`temp.next = prev;`**: Flip the arrow! Point the current node's `next` reference backwards to `prev`.
9. **`prev = temp;`**: Shift `prev` forward to point to the current node.
10. **`temp = next;`**: Shift `temp` forward to the next node we stored in step 7.
11. **`return this;`**: Once the loop completes, return the reversed list.

---

## 6. Cases Comparison
- **Empty List or Single Node**: The pointers swap successfully, and the loop either doesn't execute or runs once, leaving the list correct.
- **Multiple Nodes**: The loop marches through the list, flipping every next pointer backwards, and correctly updates the `head` and `tail` of the list.

## 7. Real-World Examples
Reversal is useful in scenarios such as:
1. Implementing an Undo feature where actions must be replayed in reverse order.
2. Browsing history navigation where you step backward through historically visited pages.

## 8. Step-by-Step Execution
Let's trace `myList.reverse()` on a list: `[1] -> [2] -> [3]` (length = 3):

1. **Initialization**:
   - Swap `head` and `tail`: `head` points to 3, `tail` points to 1.
   - `temp` is set to old head (1).
   - `prev` is set to `null`.
2. **First Iteration (`i = 0`)**:
   - `next = temp.next` $\rightarrow$ `next` points to Node 2.
   - `temp.next = prev` $\rightarrow$ Node 1's next points to `null`.
   - `prev = temp` $\rightarrow$ `prev` moves to Node 1.
   - `temp = next` $\rightarrow$ `temp` moves to Node 2.
3. **Second Iteration (`i = 1`)**:
   - `next = temp.next` $\rightarrow$ `next` points to Node 3.
   - `temp.next = prev` $\rightarrow$ Node 2's next points to Node 1.
   - `prev = temp` $\rightarrow$ `prev` moves to Node 2.
   - `temp = next` $\rightarrow$ `temp` moves to Node 3.
4. **Third Iteration (`i = 2`)**:
   - `next = temp.next` $\rightarrow$ `next` becomes `null`.
   - `temp.next = prev` $\rightarrow$ Node 3's next points to Node 2.
   - `prev = temp` $\rightarrow$ `prev` moves to Node 3.
   - `temp = next` $\rightarrow$ `temp` becomes `null`.
5. Loop terminates. The list has been successfully reversed to `[3] -> [2] -> [1] -> null`.

## 9. Lifecycle & Cleanup
Reversing a list is an in-place operation. It modifies existing node references in-place without allocating new memory block wrappers or deleting old nodes. Thus, there is no garbage collection overhead and no risk of memory leaks.

---

## 10. Common Mistakes Matrix
Here are the most common pitfalls when reversing a linked list:

| Common Mistake | Symptom | Why | How to Fix |
|---|---|---|---|
| **Changing `temp.next` before storing `next`** | The loop breaks, and subsequent nodes are lost and garbage collected. | If you assign `temp.next = prev` first, you overwrite the reference to the rest of the list before you have a pointer to navigate there. | Always store `next = temp.next` as the very first line inside the loop before modifying `temp.next`. |
| **Forgetting to update `head` and `tail`** | The internal pointers are reversed, but the list properties still point to the old head and tail, causing other operations to crash. | Reversing pointers reverses the traversal path, but the list wrapper still needs its entry and exit points updated. | Always swap `head` and `tail` using a temporary variable at the beginning of the method. |

---

## 11. Quick Recap
- Reversing a linked list flips the direction of every single pointer.
- It is done in-place with `O(1)` space and `O(n)` time.
- We swap the list's `head` and `tail` first, then use three sliding pointers (`temp`, `prev`, `next`) inside a loop to flip links one-by-one without losing access to the rest of the list.
