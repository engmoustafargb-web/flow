# 03.01 __ 14. Classes - Explained Simply

---

## 1. Analogy / Story
Imagine you own a bakery, and you have a metal cookie cutter (which we call the `Class`). 

- The metal cutter itself is not a cookie. It is simply a mold or template that defines the overall shape. This is the `Class`.
- When you press the cutter into dough, you create a real, physical cookie that you can touch and eat. This cookie is the `Object` or `Instance`.

The beautiful part is that you can use the exact same cookie cutter to make 100 cookies. Each cookie can be decorated differently, or have a different color (one green, one blue, one yellow). The cutter defines the shape, but each cookie holds its own independent properties.

---

## 2. Core Concept
- **What is a Class?**: It is a blueprint or template designed once, used to instantiate multiple objects (`objects`) sharing the same structure and behavior.
- **Why do we use it?**: To encapsulate data (properties or `properties`) and actions (methods or `functions`) together in one organized, reusable package.
- **The Problem It Solves**: It prevents manual object duplication. Without a `Class`, if we wanted to create 100 users or 100 list nodes (`nodes`), we would have to write out their structure manually for each one, which is time-consuming and error-prone.

---

## 3. Differences / Comparisons (Differences)
Let's see the difference between the blueprint and the physical instance:

| Aspect | The `Class` (Blueprint) | The `Instance` (Object) |
|---|---|---|
| **Core Idea** | The cookie cutter (engineering blueprint). | The actual physical cookie in `memory`. |
| **Instantiation** | Declared using the `class` keyword. | Created using the `new` keyword. |

Also, inside a `Class`, we categorize methods into two main groups:
- **Getter (`get color`)**: A method designed to retrieve and read the value of a property.
- **Setter (`set color`)**: A method designed to write and modify the value of a property.

---

## 4. Mental Model
Imagine a `Class` as a blank job application form designed by a company. The form specifies the required fields (Name, Age, Address). 
Calling `new Class()` is the process of printing a physical paper copy of this form and writing a specific applicant's details on it. The applicants' details differ, but they are both filling out the exact same form structure.

---

## 5. Syntax & Step-by-Step Breakdown (Syntax Breakdown)
Here is the basic syntax for creating and using a `Class` in `JavaScript`:

```javascript
class Cookie {
    constructor(color) {
        this.color = color;
    }

    getColor() {
        return this.color;
    }

    setColor(newColor) {
        this.color = newColor;
    }
}
```

Let's look at this code line-by-line to see what it does:
1. **`class Cookie`**: Declares a new class named `Cookie` (class names are capitalized by convention).
2. **`constructor(color)`**: The constructor method. This runs automatically when we instantiate a new cookie to set up initial properties.
3. **`this.color = color`**: The `this` keyword points to the specific instance currently being created in memory. It reads: "Set the color property of this current cookie to the color value passed in."
4. **`getColor()`**: A getter method that returns the current color value.
5. **`setColor(newColor)`**: A setter method that accepts a new color and updates the instance's color property.

Let's instantiate these cookies:
```javascript
let cookieOne = new Cookie('green'); // A green instance
let cookieTwo = new Cookie('blue');  // A blue instance
```

---

## 6. Cases Comparison
The context of the `this` keyword changes depending on which object invokes the method:

- **Case 1: Calling `cookieOne.getColor()`**: The `this` keyword inside the class resolves to the `cookieOne` object, returning its color: `green`.
- **Case 2: Calling `cookieTwo.getColor()`**: The `this` keyword resolves to the `cookieTwo` object, returning its color: `blue`.

---

## 7. Real-World Examples
Every data structure we build in this course relies on `Classes`. Here is how we create a blueprint for a Node (`Node`) that we will use in our `Linked List`:

```javascript
class Node {
    constructor(value) {
        this.value = value; // The data value stored in this node
        this.next = null;   // A pointer that points to the next node in the list
    }
}
```

---

## 8. Step-by-Step Execution
Let's trace what happens when we execute: `let myNode = new Node(23);`

1. The `new` keyword allocates a new, empty block of memory in the heap.
2. The `constructor` is invoked, passing the value `23` as an argument.
3. The constructor code runs, setting `this.value = 23` and `this.next = null` within the new object context.
4. The constructor returns the newly created object, and the variable `myNode` stores its reference.
The resulting memory contains: `{ value: 23, next: null }`.

---

## 9. Lifecycle & Cleanup
When we create an instance using the `new` keyword, memory is allocated. This object lives as long as there is at least one active variable pointing to it. Once those references are removed or go out of scope, the object is dereferenced and the `JavaScript engine` cleans it up automatically.

---

## 10. Common Mistakes Matrix
Here is the most common mistake developers make when working with ES6 classes:

### Mistake 1: Invoking a class constructor without the `new` keyword
- **What happens? (Symptom)**: The console throws an error: `TypeError: Class constructor Cookie cannot be invoked without 'new'`.
- **Why does it happen? (Why)**: ES6 classes strictly require the `new` operator to establish the object's context (`this`) and allocate memory. They cannot be called as normal functions.
- **How do we fix it? (Fix)**:
  Always precede the class name with the `new` keyword when instantiating:
  ```javascript
  // Incorrect:
  let c1 = Cookie('green');

  // Correct:
  let c1 = new Cookie('green');
  ```
- **The Rule that protects you**: A class constructor can only be invoked using the `new` keyword.

---

## 11. Quick Recap
To connect all the dots:
- A `Class` is the template (cookie cutter), and the `Instance` is the physical object created (the cookie).
- The `constructor` initializes properties on instantiation.
- The `this` keyword points to the specific object currently executing the code.
- **Always Remember**: `Classes` are the building blocks we will use to construct all our data structures, including `Linked Lists`, `Trees`, and `Graphs`!
